## Problem

Choosing a vector store is mostly done on vibes. The published benchmarks come
from the vendors, use different corpora, report different percentiles, and
rarely mention recall at all — so two numbers from two sources cannot be
compared, and a team ends up picking on brand recognition.

The question a team actually has is narrow: *for our corpus and our query
shape, which engine answers fast enough at acceptable recall, and what does it
cost to keep the index warm?*

## Solution

Retrieval Bench runs one workload definition against every engine it supports.
Same documents, same embeddings, same queries, same measurement code — the only
variable is the engine.

## How it works

<Architecture />

The harness treats each engine as an adapter with four methods: `index`,
`warm`, `search` and `teardown`. Everything else — timing, percentile maths,
recall scoring against a brute-force ground truth, and manifest writing — is
shared, so no engine can be measured more favourably than another by accident.

```ts title="adapters/types.ts"
export interface Adapter {
  index(docs: Document[]): Promise<void>;
  warm(queries: Query[]): Promise<void>;
  search(query: Query, k: number): Promise<string[]>;
  teardown(): Promise<void>;
}
```

Ground truth comes from an exact nearest-neighbour scan over the same corpus, so
recall is measured against what the answer actually was rather than against
another approximate index.

## Status

Two adapters work end to end. Weaviate and Pinecone are next, and the report
output is still a JSON dump rather than something you would hand to anyone.

There are no published numbers yet — the first results land in the Lab as a
proper experiment, with conditions stated, once the third adapter is in and the
measurement has been repeated enough times to be worth trusting.
